# 2.2 安装与升级

1. 在原来使用的 Edge 配置中打开侧栏。需要保留个人预约交接记录时，先用原有备份入口导出。若已使用 2.2，也可在「运行日志与通知」中单独下载偏好与计划备份。
2. 在交付文件夹核对 SHA256，再解压 Edge 构建包。已用「加载解压缩的扩展」安装的用户应将构建文件放回原扩展目录，再在 `edge://extensions` 点击「重新加载」。初次安装可选含 `manifest.json` 的解压目录。保留原目录和浏览器配置有助于维持原扩展身份与本地数据。
3. 打开侧栏，确认版本为 2.2，并检查原每日提醒是否可读。若仍显示旧版本，核对当前 Edge 配置与扩展目录。在学校网页按正常流程登录，打开座位页后再读取当前页面缓存。
4. 在「我的预约偏好」配置座位与时间，保存本日或未来某天的计划。需要新版桌面通知时，在「运行日志与通知」开启开关。操作步骤和证据要求见[智能空档指南](intelligent-booking-guide.md)。
5. Mobile PWA 构建可解压到现有 HTTPS 静态站点的同一目录与范围。用原网址打开以继续读取同一浏览器中的本地数据。手机交接继续使用二维码或 JSON。[移动端使用说明](../README.md#手机交接)

已有 Windows 每日启动任务继续使用原 PowerShell 脚本和 07:55 调度。若曾经设置过同名任务，可按[运行健康指南](runtime-health-guide.md)核对时间与结果。

## 数据迁移和备份

现有 `dlmu-daily-booking-v2` 数据库从版本 1 升到版本 2，事务内添加助手设置、日期计划、有效观察摘要、运行日志和去重记录。旧 `state` 与 `claims` 不重建。新通知开关默认为关闭，日期计划初始为空。每日固定座位可在偏好表单中作为初始编辑值，只有用户保存才写入新版偏好。旧页面阻塞迁移时，关闭占用数据库的旧扩展页面并重新加载。升级失败会回滚结构更改。

配置备份采用 SHA256 完整性检查。恢复会更新偏好、通知设置及文件所包含的日期，保留其他日期，导入的计划重新进入待核验。运行记录通过单独的日志入口导出。清理新版数据只影响新增存储。升级后若需回到旧构建，请先导出数据并保留原配置目录，旧代码对数据库版本 2 的兼容性尚未验收。

源码包包含 Git 提交中的项目文件。进入 `extension` 后执行 `npm ci` 和 `npm run verify` 可重建。依赖本机历史夹具的测试见 README。使用 `Get-FileHash -Algorithm SHA256` 可核对下载文件和 `SHA256SUMS.txt`。
