# testing

## 命令

| 命令 | 作用 | 是否需要浏览器/网络 |
|---|---|---|
| `npm test` | 34 项离线单元测试（node:test，纯函数 + mock chrome API） | 否 |
| `npm run build` | 严格 TypeScript 检查 + 三阶段 Vite 构建（面板 / content / hook） | 否 |
| `npm run check` | 产物结构校验：manifest 引用齐备、hook 无 `chrome.*`、权限未扩大 | 否 |
| `npm run test:e2e` | 真浏览器加载扩展 + 本地伪造目标源，验证实时数据全链路（23 项） | 需要已安装 Edge |
| `npm run test:restart` | 关闭浏览器再启动，验证任务恢复与 Service Worker 重建（9 项） | 需要已安装 Edge |

## 分层，不要混用结论

1. **单元测试**只证明纯逻辑正确（状态机、规则、解析、规范化）。
2. **结构校验**只证明产物与 manifest 自洽，不证明浏览器接受。
3. **端到端测试**证明扩展能在真浏览器里加载、注入、取数、渲染——但它跑在
   **本地伪造页面**上，不证明真站的数据结构与刷新时机。
4. **真站验收**必须人工登录完成，自动化不能替代。

## 端到端测试的边界（重要）

`scripts/e2e-live.mjs` 用 Playwright 路由拦截把 `https://seats.dlmu.edu.cn/**` 指向本地夹具，
目的是让 content script 按**真实 `matches` 规则**注入（没有放宽 manifest 匹配范围）。
它**不访问真站、不登录、不发真实请求**。

因此它不能证明：

- 真站 `/ic-web/reserve` 的真实响应结构；
- 登录态下的刷新频率；
- `resvInfo` / `resvStatus` 的真实取值。

## 必须人工验证的项

浏览器需手动加载 `dist` 并确认：工具栏图标点击、**原生**侧边栏（不是标签页形式）、
真站座位页的实时数据、刷新后数据更新、浏览器关闭重开后的任务恢复。

**静态测试与端到端测试都不等价于浏览器验收；未执行的项必须在报告中标记未验证。**
