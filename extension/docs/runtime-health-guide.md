# 2.2 运行健康与恢复

在日常使用的普通 Edge 配置加载扩展的 `dist` 目录。在同一配置打开学校预约页并人工登录，再从工具栏打开侧栏。实时数据来自当前标签页，历史地图、计划和上次健康摘要各自标记来源。安装和 Windows 每日启动步骤见[日常 Edge 配置与每日启动](daily-edge-installation.md)。

## 状态的依据

| 通道 | 查看什么 |
| --- | --- |
| 浏览器、扩展和后台 | 收到扩展后台回复表示已连接。后台初始化和本地提醒恢复期间显示 `WORKER_RECOVERING`。 |
| 内容脚本和业务页面 | 按当前标签的域名和业务路由识别座位页、个人预约页、学校其他页面、统一认证页及非目标页。读取座位或个人预约页时复核内容脚本的路由。 |
| 会话 | 统一认证跳转或精确匹配的座位响应返回 401 时进入 `SESSION_LOST`。个人预约页通过新的结构检查后显示已复核，随后等待新座位数据。 |
| 网络和 DOM | 分别显示新鲜、过期、等待或错误。学校页自己的响应和前台 DOM 读取是两个独立证据。无新观察会保留上次成功时刻。 |
| 本地数据库和提醒 | 数据库状态来自实际读取。核对每日提醒及最近一条日期计划提醒的闹钟名称和时间。`NONE` 表示当前没有待核对的闹钟。 |
| 任务 | 显示每日辅助任务启用、暂停或尚未配置，以及最近一次任务结果时间。 |

`HEALTHY` 表示当前座位页的网络与 DOM 观察均有效，且当前没有阻断恢复的状态。预约资格、时段可用性和提交结果各自需要证据。`WAITING_FOR_PAGE` 表示页面、内容脚本或至少一个观察通道尚未就绪。`NETWORK_ERROR` 覆盖离线与访问受限，`PARSER_ERROR` 表示结构检查失败，`DATA_STALE` 表示至少一个有效观察已超过两分钟。`TASK_PAUSED` 表示每日辅助任务暂停。连接、数据库或每日闹钟的证据不足时显示 `UNKNOWN`。

实时监听区的最近捕获时间来自经过来源、路由和编号检查的浏览器响应。运行健康的网络时间和解析时间来自最近一份通过结构检查的网络数据。DOM 有独立观察时间。日志与界面使用北京时间。读取当前页缓存或打开侧栏只更新显示，保留原观察时刻。

## 中断与恢复

1. 进入统一认证页或遇到精确 401 时，扩展记录中断门槛并暂停当前业务核验。任务设置、历史摘要和原日志保留。
2. 在原 Edge 配置的学校页面人工登录。打开官方个人预约页，等待扩展取得晚于中断时刻、结构合格的观察。空表、表格无法识别和证据不足时保持等待。
3. 回到目标座位页，等待学校页面自行产生新响应，并取得新的前台 DOM 观察。只有复核后取得的座位观察可用于恢复当前判断。
4. 要核对某个计划，打开对应区域的座位页和官方个人预约页，使用侧栏的计划核验。核对依赖日期、区域、座位、时段与官方记录的唯一匹配。结果待核验时按界面提示检查学校页。

Edge 关闭、设备关机或 Windows 用户退出期间没有页面采集。浏览器启动或后台重建时从本地存储恢复配置并重建提醒。旧的成功时间仍可查阅，当前页面和会话重新取证。唤醒和任务启动时刻受设备、用户登录状态、系统设置与 Edge 配置选择影响。学校会话有效期由学校控制。

## 本地运行记录

运行事件可按北京时间日期、座位或任务筛选，并可导出 JSON 或清空。每条事件保存编号、事件类型、时间、来源、级别、可用的座位或任务标识与固定描述。运行日志保留最近 30 天内最多 500 条事件。最后一次有效观察的本地摘要保存捕获时间、路由、座位数和来源。两者均使用字段白名单。网络正文、DOM 原始 `title`、登录字段与认证凭据不进入这些运行记录。

事件与去重记录保存在扩展配置内的 IndexedDB。已有每日任务的记录沿用同一数据库。新建配置备份仅含助手偏好、计划和提醒设置，计划的既有核验结果和运行记录不随配置导入。确需留档时单独导出事件。关闭提醒后仍可查阅产生的运行事件。桌面提醒已被 Edge 接收时记录 `NOTIFICATION_SENT`，系统是否展示或用户是否看见需要另行核实。
