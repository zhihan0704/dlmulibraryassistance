# 智能空档建议与多日期计划

## 保存偏好和计划

1. 在日常使用的 Edge 配置里打开图书馆官方座位页面，按学校流程登录。进入目标区域并等页面完成自己的数据加载。
2. 在侧栏「我的预约偏好」选择首选座位、日期和开始、结束时间。座位的完整身份由区域 ID、设备 ID 和编号组成。看到相同编号时，仍需核对区域。
3. 需要在首选座位上调整时段时，开启时间调整并填写允许范围。这个范围须覆盖首选时段。允许跨午夜，计划日期取北京时间的开始日期。
4. 需要比较备用座位时，开启备用座位并按优先顺序配置具体座位。需要缩短时长时另行开启缩短，并填写本人最短可接受时长。时长以整分钟计算。
5. 保存对应日期的计划。可分别设置优先级和本地提醒。更新同一日期会更新该日计划，其他日期各自保存。原有每日固定座位提醒单独管理，现有配置中的 08:00 是提醒时间，学校的实际开放时间仍需证实。

「智能空档建议」显示分析结果和实际观察时间。当前座位页面尚无合格的新数据时，可以按平时的方式打开所需区域，让学校页面自然加载。会话过期后，先在原 Edge 窗口手动完成认证，再打开个人预约页和目标座位页，等待新的页面观察。

## 怎样得出建议

- 先按区域、设备和座位编号唯一匹配数据。核验模式、会话、来源和新鲜度。默认新鲜度上限为两分钟，以扩展真实收到观察的时间计算。
- 统一以北京时间展示结果。时间计算使用半开区间 `[开始, 结束)`，例如结束于 20:00 的区间与开始于 20:00 的区间相邻。验证区间覆盖，合并相邻同状态区间。区间重叠、缺口或未知状态会让相关分析范围待核验。
- 只在完整已知的范围内取连续空档。候选起点不能早于当前时间，必须满足已核验的起点步长。候选时长最多为原计划时长和已核验最长时长中的较小值。开启缩短后，最短时长取个人下限和学校已核验下限中的较大值。
- 先比较首选座位，再按用户指定的备用顺序比较。在每个座位内，原时段完全吻合优先。其余候选按设定优先比较可保留时长、连续空档及距离首选开始的远近。条件相同时优先较早开始的时段。
- 每个候选显示座位顺序、时段调整、缩短分钟数、连续空档长度、证据状态和采集时间。首选证据待核验时，独立通过核验的备用项仅作为备选，首选偏好继续保留。

| 结果 | 如何理解 |
| --- | --- |
| `READY` | 有证据支持的候选时段，供本人核对。候选仍需由本人在学校页面操作。 |
| `NEEDS_REVIEW` | 时间覆盖、状态含义、时效、资格或规则尚有缺口，或存在冲突。 |
| `NO_MATCH` | 在已核验范围内，当前偏好和资格条件没有合格结果。 |

学校页面自然产生的座位响应可以说明观察到了哪张座位，以及收到了什么原始字段。`devStatus=0`、`openState` 和空 `resvInfo` 都无法独立证明可用。当前真实数据适配仍缺少完整时段覆盖、状态含义和个人预约资格的证据。因此真实页面的候选会保留待核验状态。最短时长与闭馆信息曾出现冲突，预约开放时刻、最长时长、预约日期范围和个人限制也需要按区域和日期核验。历史的 152 座位快照仅供查阅历史编号与布局。

### 合成示例

假设 `MOCK-01` 的首选时段为 19:00–20:00，允许范围为 18:00–22:00，合成规则下限为 30 分钟。完整的合成时间轴中，该座位在 19:15–19:45 和 21:00–22:00 有空档。

- 开启调整、关闭缩短时，建议为 21:00–22:00。
- 同时开启缩短并优先接近原时间时，19:15–19:45 排在前面。优先保留时长时，21:00–22:00 排在前面。
- 把合成规则改成未知或冲突，结果转为待核验。以上编号、时长与空档都是测试数据。

## 核对本人已完成的学校预约

在学校网站自行完成操作后，保持目标区域座位页和个人预约页可见，在该日期计划中点击「核对学校预约」。扩展只读核对计划日期、楼层、区域、座位身份、起止时间与个人预约页是否唯一吻合。任何一项缺失、多条匹配、过期或会话中断均需重新检查。如果本人选的是另一个时段或已明确配置的备用座位，先把计划改为本人实际选择，再核对该日期。预约核验结果与空档建议分开显示。

配置备份可用于保存或恢复多日期计划、偏好和通知设置。恢复后，计划等待用新的官方观察核对。运行日志另行查询或导出。
