# 2.2 当前页面数据通道

MAIN world 旁路观察学校座位页正常产生的 `GET /ic-web/reserve`，同时核对请求和最终响应的精确来源与路径。XHR 和 fetch 继续按网页原方式工作。桥接消息只传业务字段白名单、捕获编号、传输方式、请求开始时的座位路由、响应捕获时刻及必要的 HTTP 状态。查询串、请求头、凭据和身份字段均不进入桥接数据。

隔离环境中的内容脚本再次检查消息来源、当前路由、捕获时间、编号和座位身份。旁路短期缓存最多三条观察，最长 30 秒。读取缓存保留原捕获编号和时间。路由切换、旧响应、重复编号及不匹配的区域会被过滤。结构校验失败时显示错误并保留上次成功时间。精确匹配的 401 进入认证中断流程，403 显示访问受限并等待新证据。浏览器离线与恢复也会改变本地健康状态。恢复在线以后等待网页的新数据。

同源桥接仅提供页面观察，数据没有独立的官方签名。旁路跳过未识别的最终地址、非 `GET` 方法、非座位路由、特殊 fetch 初始化访问器与二进制 XHR 响应。空 `resvInfo`、`devStatus=0`、`openState=1` 与 `resvStatus` 缺少已核验的可预约状态映射，原始值仅作观察使用。状态变化分类见[实时监听架构](realtime-monitoring-architecture.md)。

侧栏的「读取当前页面缓存」读取当前标签内存。等待数据时，可在学校网页正常切换目标区域或手动刷新。出现经过校验的新响应时才更新最近一次成功网络观察。DOM 在标签页前台批量读取，页面隐藏时断开观察。若网页在后台正常收到响应，仍可被动观察网络。网络与 DOM 分别记录新鲜度，超过两分钟没有有效新观察时显示过期。全部时间为北京时间下的本机捕获或 DOM 观察时刻。

内容脚本提交给后台的运行观察仅使用时间、路由、座位数、变更类型和经过校验的座位身份等元数据。座位响应正文与 DOM 原始指纹留在当前页面观察链路。扩展重新启动时，历史地图、上次成功摘要和新实时观察继续分开显示。[运行健康与恢复](runtime-health-guide.md)

## 日常 Edge 人工核验

1. 在日常使用的普通 Edge 配置中打开 `edge://extensions`，加载或重载构建目录 `extension/dist`。打开学校首页，使用学校正常流程人工登录。[学校预约首页](https://seats.dlmu.edu.cn/#/ic/home)
2. 打开座位页和侧栏，核对当前路由和区域、XHR/fetch 计数、最近成功响应与 DOM 时间。选中目标座位，查看该座位最近一次变化的来源和时间。
3. 点击「读取当前页面缓存」，核对网络捕获计数和原捕获时间。随后在学校标签页手动刷新一次，核对新响应到达后的捕获时间。
4. 正常切换页面日期或区域。若出现真实变化，核对变化类型、事件日志和两个通道的时间。若没有新数据，记录当时的等待或过期状态。
5. 自然遇到认证过期时，观察读取暂停和设置保留。完成手动登录后打开官方个人预约页，等待结构合格的观察。回到座位页检查新的基线。无法识别的表格和空表保持待核验。

以上为只读核验流程。真实 Edge 配置、自然认证过期后的完整恢复与学校页面字段的含义需要分别实测。此前版本的验收证据可按[实时监测验收报告](../reports/realtime-monitoring-acceptance.md)查阅。
