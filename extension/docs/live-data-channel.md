# 当前页面数据通道

MAIN world 旁路观察学校页自己产生的 `GET /ic-web/reserve`。它验证请求和最终响应的精确来源与路径，支持 XHR 和 fetch。现有网页请求、原始响应和 Promise 保持原行为。正文白名单排除身份字段；认证状态提示仅传 401 或 403 等必要元数据。消息保留捕获编号、传输方式和座位路由，查询串和请求头不传递。

内容脚本在隔离环境中复核消息来源、路由、捕获时间和座位身份。旁路缓存仅保留短期的最近三条观察。重放保留原捕获编号。抓到格式异常、混合区域、重复座位或不匹配的响应时，界面会保留上次成功样本的时间，同时把有效性标为待核验。缺少服务器时间戳时只显示北京时间下的本机响应捕获或 DOM 观察时间。

同源消息是网页观察通道，无法作为独立的官方签名。旁路会跳过未识别的最终地址、未获授权的请求方法、非座位路由、特殊 fetch 初始化访问器与二进制 XHR 响应。可见的 DOM 样式和预约字段只表示所观察到的内容。空 `resvInfo`、`devStatus=0`、`openState=1` 和 `resvStatus` 均不用于推断可预约。

侧栏的「读取当前页面缓存」只读取当前标签内存。等待数据时可自行在学校网页切换到目标区域或手动刷新。刷新以后以新的响应捕获时刻为准；超过两分钟无新观察会显示过期。DOM 在标签页前台批量读取，隐藏时断开；后台网页自行返回的网络响应仍可被动观察。网页结构变化时当前读取失败并显示提示，历史地图保留独立的来源标识。

## 日常 Edge 人工核验

1. 在 `edge://extensions` 重载本地 `extension/dist`，打开[学校首页](https://seats.dlmu.edu.cn/#/ic/home)，使用学校正常流程人工登录。
2. 打开座位页和侧栏的实时监听区，查看 XHR/fetch 计数、最近响应、当前路由和区域。点击座位查看它最近的响应与 DOM 变化时间。
3. 在侧栏点击「读取当前页面缓存」，确认不会增加网络捕获计数。然后在学校标签页手动刷新一次，确认收到新响应才出现新的捕获时间。
4. 正常切换页面的日期或区域，记录 DOM 或响应真实变化时的显示。页面数据无变化时记录观察结果，等待真实变化再验收。
5. 自然遇到登录过期时，观察读取暂停与设置保留。完成手动登录后进入官方个人预约页，等待有效记录复核，再回到座位页观察新的基线。空表和无法识别的表格保持待核验。

以上步骤保持只读。通过合成数据验收的功能与真实学校页面验收状态分别记录在[验收报告](../reports/realtime-monitoring-acceptance.md)。
