# DLMU Library Assistant 2.0 验收

## 第一阶段

已把每日固定座位任务接入原扩展侧边栏、Manifest V3 Worker、单次闹钟和独立 IndexedDB。07:55 准备，08:00 提醒，08:01 尝试核验，时区为 `Asia/Shanghai`。例如 2026-11-06 08:00 的使用日期是 11 月 7 日。月份、年份和休眠恢复都以北京时间日历和当日窗口判定。最多保存一个固定任务；读取锁以任务、日期、座位、时段和阶段区分。错过窗口后等待次日。旧模拟、个人预约、地图、现场签到准备和移动端继续保留。

固定座位绑定来自学校页正常产生的 `GET /ic-web/reserve` 响应和对应路由及座位 DOM。响应只用于身份匹配；空 `resvInfo` 与原始状态码无法证明空闲。个人页核验使用可见表格中完整编号、楼层、区域、座位、日期、起止时间和明确状态。一条唯一有效记录才显示匹配；没有观察到记录时仍需核对分页、筛选和会话。认证页被识别时等待人工登录，当前窗口内收到有效页面事件才重查。浏览器未向扩展暴露统一认证页地址时会显示页面待核对。

生产提交验收未达成。2026-11-06 学校首页公开入口返回 HTTP 307 并重定向至 `atrust.dlmu.edu.cn`。日常 Edge 检查中，computer-use 工具无法可靠确定当前浏览器 URL，停止操作。学校公开指南确认预约自习室需预约，但本轮未核实 08:00 开放规则、适用最短时长、资格与正式提交或成功契约。历史帮助页 60 分钟与探针 30 分钟仍标记 `NEEDS_REVIEW`。测试中的模拟执行先写入尝试标记，超时转为待核验，验证同一预约前始终阻断再次提交。当前发布没有生产提交适配器。[学校智慧校园指南](https://iec.dlmu.edu.cn/info/1017/7063.htm)

Windows 已注册当前用户任务 `DLMU Library Assistant 2.0 Daily Edge`。系统返回 `Ready`，下次为 2026-11-07 07:55（本机北京时间），请求睡眠唤醒。任务尚未实际触发。日常 Edge 当前配置中的新版安装、真实触发、唤醒、已登录页的数据绑定和人工登录恢复仍待实测。配置和启动复核见[安装说明](../docs/daily-edge-installation.md)。

## 第二阶段

`seat-timeline.ts` 定义可信来源、相同座位、完整覆盖与新鲜度。`free-interval-engine.ts` 仅在覆盖完整且时段已知时计算连续空档。`dynamic-booking-policy.ts` 要求已核验资格和时长，用户明确启用后才建议调整时间，保留目标座位和使用时长。`availability-watcher.ts` 对被动观察去重，区分新变化、重复观察、过期、未知和会话失效，并有观察时限和次数边界。

阶段二目前是纯逻辑模块与测试。真实响应的覆盖范围、状态语义、资格和开放规则缺少足够证据，生产数据只进入未核验路径。真实推送能力尚未核实。当前没有新增生产轮询、动态自动预约或变更其他用户预约。
