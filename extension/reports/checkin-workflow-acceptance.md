# 签到流程验收 1.0.0

1. 电脑正常登录学校，在个人预约页只读识别完整记录。
2. 本地生成多预约任务，按用户偏好提醒；校方窗口不明确时为UNKNOWN。
3. QR/JSON交接到手机。两端使用同一模型和计算，不共享登录。
4. 本人携卡在学校机器刷卡；软件无NFC/RFID模拟或签到接口。
5. 点击按钮保存USER_REPORTED_CARD_SWIPED事件，任务为AWAITING_OFFICIAL_CONFIRMATION。
6. 电脑再次观察同一身份记录，只有精确官方文字“已签到”“签到成功”“使用中（已签到）”才记录OFFICIAL_CONFIRMED，并追加观察时间和来源。无结果时继续等待，不按1027、1029、1093推断。
7. 官方取消记录仅使本地任务过期并提醒，不执行取消。记录消失不当作取消。

签到纯状态机测试、共享数据库真实浏览器事务测试、扩展端完整合成页面流程已通过。数据包括实际本机观察时间，证据与可信度清晰区分。二维码与备份没有学校签名，来源标签不构成官方证明。

本轮未替用户刷卡、未现场签到、未实际核验学校状态文字与设备结果的对应关系。精确文字识别代表“官方页面显示该文字”，不能宣称超出页面的学校服务端保证。历史规则最短时长及闭馆时刻仍冲突，NEEDS_REVIEW保留。
